# Live Score Game-By-Game Detail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Click a live card or a Results row and see the match game by game (server, game score, best-effort point trail), persisted permanently on the VPS Postgres.

**Architecture:** Each poll tick, diff the new `LiveMatchState` against the previous one per match. When a game closes, write one `match_game_events` row that carries the observed point trail. `GET /api/scores/{match_id}/games` returns the rows. One modal, opened from both card types, refetches when the live score changes.

**Spec:** `docs/superpowers/specs/2026-09-08-live-score-game-log-design.md` (read it first, it holds the reasoning).

**Revised 2026-10-12.** Nine tasks became five. Removed: the metadata half of the endpoint, the `useMatchGameLog` composable, the polling task, the `GameEventFields` dataclass, three redundant columns/indexes and the DB-polluting tests. Added: the point trail and the Results tab wiring.

## Global Constraints

- Singles only.
- Game rows are exact. The point trail is best effort and labeled so in the UI.
- Data lives in VPS Postgres via Alembic only. Generate the migration against local Docker `te4-pg` (Postgres, not SQLite). Never use the Supabase MCP for this table (stale copy). `infra/deploy.sh` applies it on the VPS.
- Inserts use `add` + `commit` inside `try/except IntegrityError`, as in `stats_service._try_finish_match`. No dialect-specific SQL.
- `GameServer.live_state` is parsed once per singles server per tick and shared.
- The scraper must never let a game-log failure break the broadcast. Scraper User-Agent stays `TennisTracker/1.0` (do not touch it).
- No frontend test framework. Verify the UI manually.
- `asyncio_mode = "auto"` is set in `pyproject.toml`, so tests do not need `@pytest.mark.asyncio`.
- No test may write to the dev database. DB tests inject an in-memory SQLite session factory.

- [ ] **Step 2: Implement `record_tick`.**

```python
async def record_tick(self, states: dict[str, LiveMatchState]) -> None:
    events = [e for mid, cur in states.items() if (e := self.step(mid, cur))]
    for stale in self._tracked.keys() - states.keys():
        del self._tracked[stale]
    for event in events:
        await self._insert(event)
```

`_insert` is the `add` + `commit` idiom. `IntegrityError` rolls back and logs at debug. Any other exception rolls back and logs an error. Neither is raised. `get_game_log_service()` is the singleton getter, same pattern as `get_scraper_service()`.

```python
@router.get("/{match_id}/games", response_model=list[GameEventOut],
            summary="Game-by-game history for a match")
@limiter.limit("60/minute")
async def get_match_games(
    request: Request, match_id: str, db: Annotated[AsyncSession, Depends(get_db)],
) -> list[MatchGameEvent]:
    result = await db.execute(
        select(MatchGameEvent)
        .where(MatchGameEvent.match_id == match_id)
        .order_by(MatchGameEvent.set_number, MatchGameEvent.game_number)
    )
    return list(result.scalars().all())
```

## Deploy

Push to `ionos-migration`, then on the VPS `cd /var/www/te4 && bash infra/deploy.sh`. It runs `alembic upgrade head` against the VPS Postgres and restarts `te4-backend`. Cloudflare Pages builds the frontend on push. History starts accumulating after the restart, so earlier matches stay empty.
